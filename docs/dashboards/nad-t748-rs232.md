## What this is

A NAD T748v2 is a 7.1-channel A/V receiver from 2009 with no network stack.
The only remote-control surface is a DB-9 RS-232 port on the back that
implements NAD's proprietary serial protocol. This dashboard turns that
serial port into a fully instrumented IoT device — every volume tweak,
source change, and listening-mode switch is captured, trended, and
alert-able.

The gateway is a custom service on a Raspberry Pi (see the
`hcc-nad-rs232` repo) that polls the receiver over a StarTech FTDI USB-to-
RS232 cable every 2 seconds, exposes `/status` as JSON, and publishes a
Prometheus metrics endpoint.

## Dashboard sections

### 🎛 LIVE STATE (row 1)
Six stat panels that read the receiver right now:
- **Last Update** — seconds since the most recent successful poll. Goes
  magenta if the RS-232 link goes quiet.
- **Power** — On/Standby, text-mapped from the binary protocol response.
- **Volume** — current setting in dB. The receiver's internal range is
  −99 to +19; we clamp display to −80 to 0 dB for readability.
- **Mute** — boolean, colored panel background.
- **Source** — the active input (CD, Tuner, DVD, Video 1–4, AUX, MP, USB).
- **Listening Mode** — Stereo, DD5.1, DTS, EARS, Enhanced Stereo, etc.

### 🎚 AUDIO PROFILE (row 2)
Volume as a dial gauge (single magenta "desk lamp" per the dashboard
contract — this is the one panel that's meant to pull the eye), plus
bass/treble trim, tone defeat state, front-panel dimmer state, and
firmware/model stamp.

### 🔗 RS-232 LINK — COMMAND CENTER (row 3)
Health of the RS-232 service itself. Commands sent, poll cycles, total
errors, commands-per-poll ratio, error ratio. If the error ratio creeps
above 0 for more than a cycle, the cable or the gateway needs attention.

### 📡 RS-232 TELEMETRY (row 4)
Two time series panels: command + poll rates (ops/sec) and RS-232 latency
+ error timeline. Baseline latency is ~40ms per poll; anything above 200ms
sustained is suspicious.

### 🎛 SOURCE & LISTENING MODE — TIMELINE (row 5)
Two `status-history` panels showing what source and listening mode were
active over time. Fills in solid bars with palette-locked colors. Useful
for answering "what was I watching last Tuesday?"

### 📈 VOLUME HISTORY (row 6)
Time-series of volume + peak/avg/min stat panels over the selected range.
Catches late-night volume creep.

### 🕒 SESSION STATS (row 7)
Range-windowed counters: time powered on, power cycles, mute toggles,
source changes. These feed usage analytics — the receiver is not a
chatty device, and these counters are the only "user behavior" signal.

## Engineering notes

- **2s poll interval.** The NAD protocol is synchronous half-duplex, so
  polling faster would starve the command path. 2s is the sweet spot
  between freshness and serial bus contention.
- **All state is inferred from polling.** The receiver does not push
  state changes. Mute toggled on the physical remote won't show in the
  dashboard until the next poll completes.
- **status-history over state-timeline.** Grafana's state-timeline stacks
  states vertically; status-history shows them as a solid horizontal bar
  which scans better at-a-glance.
- **Volume unit conversion.** The receiver reports volume as an integer
  from 0–118 (step-mapped to its dB range). The exporter converts to dB
  in-band; the dashboard never sees raw protocol values.

## Known quirks

- On cold start the receiver answers a few polls with `Main.Model=T747`
  before settling to `T748`. Firmware panel may blink for the first ~30s
  after power-on.
- Listening mode "Enhanced Stereo" is reported as `EnhancedStereo` (no
  space) by the protocol — the timeline color mapping accounts for both
  spellings.
